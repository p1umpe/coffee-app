# Simple Coffee — Решения и ADR (v0.2 от 24.09.2026)

Зафиксировано со слов владельца. Статус: утверждено, в работу.

## ADR-001. Мобильный стек — Flutter (Dart)

**Контекст:** у владельца нет опыта мобильной разработки, нужна простота + задел под игру.
**Решение: Flutter.**
- Один код на iOS + Android, один язык Dart.
- Лучший DX для новичка: hot-reload, огромная документация на русском, виджеты «из коробки».
- Кастомный тёплый UI Simple Coffee (скругления, лис) делается проще, чем на нативе.
- Критично под будущее: игра «лис бежит за зёрнами» делается на **Flame Engine** — это нативный игровой движок для Flutter на том же Dart. Не нужен Unity / второй разработчик. Игру просто докрутим как отдельный таб/пакет `game_fox_run`.
- Альтернатива React Native отклонена: для игры пришлось бы тащить Unity/Unreal + мост, это 2 стека вместо 1.

**Что учить новичку:** Dart (1 неделя) → Flutter widgets → Riverpod (стейт) → Flame (позже, v2.0).

## ADR-002. Лояльность «Кружка = печать» (цифровая карточка)

**Было:** бумажные карточки: взял в кружке (попить в кофейне) — печать, взял с собой — без печати, но дешевле.
**Стало (в приложении):**
- Два режима выполнения заказа (fulfillment): `DINE_IN` (в кружке, в зале) и `TAKEAWAY` (с собой).
- `DINE_IN`: цена = базовая (например 320₽), +1 печать за каждый кофейный напиток в чеке. 6 печатей = 7-й кофе бесплатно (в кружке).
- `TAKEAWAY`: цена = базовая − скидка (например −30₽ / −10%), печатей НЕТ.
- Печать начисляется НЕ в момент оплаты, а в момент подтверждения бариста «Выдано в кружке» (скан QR гостя + кнопка в КДС). Это защита от фрода.
- Что даёт печать: только кофе/напитки (не еда, не зерно). Один заказ — максимум N печатей = количеству напитков.
- Карточка в приложении: 6 кружек-лисичек, прогресс, «до бесплатного осталось 2».
- Бесплатный кофе: отдельный купон с QR + TTL 30 дней, сгорание честно показываем.

Открытый вопрос к тебе: подтверждаешь 6+1? Или 5+1 / 8+1? Пока ставлю 6+1 как стандарт кофеен.

## ADR-003. Касса — iiko (единственная интеграция MVP)

**Решение:** iikoCloud API + iikoFront.
- Меню тянем из iiko (номенклатура, цены, стоп-листы) → наш backend кэширует, но source of truth — iiko.
- Заказ из приложения создаём в iiko как `deliveryOrder` с типом `pickup`, полями `dineIn: true/false`, номером А-12.
- Статусы кухни (готовится/готов) слушаем через webhook iiko → пушим гостю.
- Выдача + начисление печатей — закрытие заказа в iikoFront бариста.
- Фискализация через iiko (ФЗ-54), нам не нужен отдельный ОФД-модуль в MVP.

## ADR-004. Только самовывоз (без доставки в MVP и v1.1)

Убираем доставку из скоупа полностью. Два подтипа самовывоза:
- Заказал заранее → забрал сам (с собой или в кружке).
- Заказал у стойки через QR на столе (dine-in без очереди на кассе).
Курьеров, зон, СДЭК — нет. Это упрощает архитектуру на 30%.

## ADR-005. Игра «Лис бежит за зёрнами» — отложена до v2.0, но задел сейчас

**Идея:** Subway Surfers-лайк: лис бежит, собирает зёрна, уворачивается от луж/стульев. Коротает ожидание 7 минут + вовлекает.
**Решение сейчас:**
- В архитектуре выделяем `packages/game_stub` — пустой модуль с контрактом: `GameService { getBalance(beans), spendBeans(), grantBonus() }`.
- В дизайне резервируем таб/баннер «Скоро: игра от Лиса», но не разрабатываем.
- В v2.0: Flame + спрайты лиса в фирменных цветах, зёрна = внутренняя валюта, которую можно менять на сироп/печать. Офлайн-режим игры обязателен.
- Почему не сейчас: игра не влияет на North Star (предзаказы), но съест 3-4 недели. Сначала ядро «заказ+печати».
